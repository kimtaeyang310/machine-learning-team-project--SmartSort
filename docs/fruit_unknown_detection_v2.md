# 과일 종류 분류 v2: 개체 분리·전처리 비교·과일별 95% 기준

## 실행

기존 가상환경에서 `main.py` 4번 또는 다음 명령으로 학습합니다.

```powershell
& ./.venv-yolo/Scripts/python.exe -m src.train_fruit_classifier
& ./.venv-yolo/Scripts/python.exe -m src.evaluate_fruit_classifier
& ./.venv-yolo/Scripts/python.exe -m src.predict data/predict_list
```

`main.py` 3번은 통합 예측, 5번은 저장된 기준 재평가입니다.
학습 명령은 종류 모델만 교체합니다. 기존 숙도 모델과 숙도용 메타데이터 분할은 변경하지 않습니다.
이전 종류 모델은 실행 보고서 폴더의 `previous_classifier.joblib`에 보관합니다.
선택된 모델도 `selected_classifier.joblib`에 별도로 보관합니다.
v1 종류 모델 파일도 예측·재평가에서 계속 읽을 수 있습니다.

### teamTC 실행 환경 호환

종류 분류 헤드는 학습 후 NumPy 계수·절편·클래스와 softmax 계산으로 저장합니다.
따라서 저장 모델을 읽을 때 scikit-learn `LogisticRegression`의 버전별 내부 속성에 의존하지 않습니다.
현재 `.venv-yolo`의 scikit-learn 1.9.1과 `teamTC`의 1.7.2 사이에서 발생하던
`multi_class` 속성 오류를 피할 수 있습니다. 신경망 가중치·분류 계수·모름 임계값은 그대로 유지합니다.

기존 sklearn 객체 형식의 종류 모델을 변환해야 한다면, 그 모델을 학습한 환경에서 다음을 실행합니다.

```powershell
& ./.venv-yolo/Scripts/python.exe scripts/convert_fruit_classifier.py
```

변환 전에 학습 계수로 계산한 확률을 원래 분류기와 비교하고, 이전 파일과 변환 보고서를
`outputs/fruit_classifier/compatibility_실행시각/`에 보관합니다. 이후 4번 학습 결과도 자동으로 이 형식을 사용합니다.
현재 변환된 모델은 VS Code의 기존 `teamTC` 환경에서 `main.py`를 실행할 수 있습니다.

## 1. 개체 ID 단위 분리

귤·토마토는 `과일 종류 + 개체 ID`를 그룹으로 묶습니다. 같은 개체의 다른 날짜·각도·조명 사진은
하나의 그룹입니다. 바나나는 기존 원본 그룹을 유지합니다.
기존 Train 안에서 약 60% Train / 20% Calibration / 20% Selection을 구성합니다.
비율은 사진과 그룹 분포에 따라 달라집니다.

과일마다 개체 수의 약 20%씩을 Calibration·Selection에 배정하고 나머지를 Train으로 둡니다.
고정된 500개 시드로 후보를 만들며, 이미지 점수나 Test 결과를 보지 않은 상태에서
가능한 숙도 구성을 보존하고 숙도별 사진 수의 목표 비율을 가장 잘 맞추는 분할을 선택합니다.
Train에는 모든 숙도를 남깁니다. 해당 숙도의 독립 개체가 2개 이상이면 Calibration에도,
3개 이상이면 Selection에도 배정합니다. 이 조건을 만족하지 못하면 학습을 중단합니다.
예를 들어 귤 적숙 개체가 2개뿐인 현재 자료에서는 Selection에 적숙 귤이 없습니다.
이는 자료 부족에 따른 공백이며 사진을 복제하거나 개체 중복으로 채우지 않습니다.
같은 개체 ID가 기존 Test와도 겹치면 자동으로 옮기지 않고 오류로 중단합니다.

| 분할 | 용도 |
|---|---|
| Train | 분류 헤드 학습, 임베딩 기준 벡터 구성 |
| Calibration | 과일별 약 95% 통과 임계값 계산 |
| Selection | 전처리·점수 방식 선택 |
| 기존 Test | 정책 확정 후 회귀 비교만 수행 |

포도·레몬은 기존처럼 유사 이미지 그룹을 유지하며 Selection/Test로 나눕니다.
Calibration 표에 표시하는 미지 과일 오수락률은 같은 미지 Selection 자료의 값입니다.
별도의 미지 Calibration 자료가 있는 것으로 해석하지 마세요.

기존 Test는 앞서 오류 원인 분석에 사용됐으므로 새 독립 최종 평가 자료가 아닙니다.
이번 코드에서는 Test 점수로 전처리·임계값·방법을 선택하지 않지만,
최종 일반화 성능을 발표하려면 새로운 개체·미지 과일 자료가 필요합니다.

## 2. 로컬 다양성 보완

새 독립 개체 사진은 추가하지 않았습니다. 현재 로컬 자료만 사용합니다.
반복 촬영한 소수 개체가 학습을 지배하지 않도록 분류 헤드에 다음 가중치를 적용합니다.

1. 과일 종류별 총 학습 가중치를 같게 합니다.
2. 각 과일 안에서 숙도별 총 가중치를 같게 합니다.
3. 각 과일·숙도 안에서 개체별 총 가중치를 같게 합니다.
4. 같은 개체·숙도의 사진이 여러 장이면 그 가중치를 나누어 갖습니다.

예를 들어 같은 숙도의 T01 사진 10장과 T02 사진 1장은 개체별 총 가중치가 같습니다.
학습에 배정된 사진은 모두 기준 벡터에 포함됩니다. Calibration·Selection·Test 사진은 넣지 않습니다.
이는 기존 다양성을 학습에 반영하는 보완이며, 새로운 개체를 확보한 것과 같지 않습니다.
`specimen_inventory.csv`에서 개체별 사진 수·숙도·분할·학습 가중치를 확인할 수 있습니다.
외부 이미지의 ID가 실제 독립 개체를 뜻하는지는 원본 출처·촬영 기록 확인이 추가로 필요합니다.

## 3. 전처리 비교

세 방식 모두 과일 종류를 알기 전에 같은 규칙으로 적용하며 색상 자체를 바꾸지 않습니다.
숙도용 K-means 마스크나 과일별 색상 조건을 재사용하지 않습니다.

| 방식 | 동작 |
|---|---|
| `center_crop` | 기존 ImageNet Resize + 중앙 224 crop |
| `letterbox` | 전체 비율을 유지하고 흰 여백을 더해 224 정사각형 구성 |
| `foreground_crop` | 작은 HSV 영상에서 채도·밝기로 전경 후보를 찾고, 유의미한 성분의 합집합에 여백을 둬 crop 후 letterbox |

전경 후보가 없으면 전체 사진 letterbox로 돌아갑니다. 이는 배경 분리가 보장되는 검출기가 아니므로
색 있는 배경이나 저채도 물체에서 효과가 떨어질 수 있습니다. 최종 방식은 실제 Selection 비교로 선택합니다.
과일 영역 방식이 무조건 선택되는 것은 아닙니다.

각 전처리에 대해 같은 ImageNet MobileNetV3-small 고정 특징 추출기와 개체 가중치 분류 헤드를 사용합니다.
캐시는 이미지 내용·특징 추출기 상태·전처리 방식/코드·Torch/Torchvision 버전에 따라 분리됩니다.
Train 기준 벡터와 추론 영상은 저장된 동일 전처리로 처리합니다.

## 4. 과일별 95% 기준

MSP 이상 점수(`1-최대 확률`)와 임베딩 최근접 5개 평균 코사인 거리를 비교합니다.
각 방식에서 Calibration 사진을 **실제 정답 과일별**로 확인하고, 그 과일의 전체 사진 중
최소 95%가 **종류도 맞고 거부도 되지 않도록** 임계값을 계산합니다.
정답 종류를 맞힌 사진 점수의 95백분위수(`higher`)에서 시작하되, 종류 오분류가 있는 경우
정답 과일 전체 수의 95%를 통과시키는 데 필요한 순위까지 기준을 보완합니다.
종류 오분류 사진으로 다른 과일의 기준을 느슨하게 만들지는 않습니다.

실제 과일별 Calibration 사진이 10장 미만이거나 종류 정확도 자체가 95%에 못 미쳐
조건을 충족할 수 없다면 해당 전처리 후보를 제외하고 `invalid_candidates.json`에 이유를 남깁니다.
모든 후보가 제외되면 기존 모델을 유지하며 중단합니다.
추론 시에는 정답을 모르므로 **예측 종류에 해당하는 저장 임계값**을 적용합니다.
점수가 임계값보다 클 때만 거부하며 같은 값은 통과합니다.
배치 크기에 따른 float32 코사인 거리의 미세한 반올림 차이로 경계 사진이 뒤집히지 않도록,
저장 임계값에 0.000001의 수치 여유를 포함합니다. 평가와 한 장 예측 모두 같은 저장값을 사용합니다.
Selection·기존 Test에서 같은 95% 통과를 보장하지 않습니다.

전처리 3종 × 점수 2종의 과일별 기준 6개가 선택 후보입니다. 공통 임계값 6개도 비교용으로 기록하지만
선택 대상은 아닙니다. Selection에서 다음 순서로 선택합니다.

1. 포도·레몬 전체 오수락률 최소
2. 알려진 과일별 평균 오류율(거부 또는 종류 오분류) 최소
3. 토마토 오거부율 최소
4. 동률이면 임베딩 거리 우선, 다시 동률이면 center_crop → letterbox → foreground_crop

정책을 확정·저장한 다음에만 선택된 방식으로 기존 Test의 특징을 계산하고 평가합니다.
Test 결과가 좋지 않더라도 해당 실행 안에서 다른 후보로 바꾸지 않습니다.
선택용 미지 자료가 포도·레몬 40장뿐이라는 한계가 있습니다.

## 결과 파일

`outputs/fruit_classifier/specimen_v2_실행시각/`에 저장합니다.

- `split_manifest.json`: 사진 경로, 개체 그룹, 원래 그룹, 분할, 내용 해시
- `specimen_inventory.csv`: 개체·숙도·분할별 사진 수와 학습 가중치
- `stage_coverage.csv`: 숙도별 사진 수·독립 개체 수와 부족한 분할 확인
- `candidate_comparison.csv`: 최대 12개 비교 조건의 Selection 결과
- `invalid_candidates.json`: 검증 통과 조건을 충족하지 못해 제외한 후보
- `experiment_summary.md`: 비교표와 선택 기준
- `frozen_policy.json`: Test 평가 전 확정한 선택 방식·임계값·모델 해시
- `previous_classifier.joblib`, `selected_classifier.joblib`: 이전 모델·선택 모델
- `report.md`, `report.json`: Calibration·Selection·기존 Test 오류 건수와 비율
- `predictions.csv`: 선택 전처리에서 두 점수의 사진별 수락 여부·점수·실제 적용 임계값

오류율 분모는 각각 알려진 과일 전체 사진 수, 모르는 과일 전체 사진 수입니다.
종류 오분류, 알려진 과일 오거부, 모르는 과일 오수락을 구분합니다.
폴더 예측은 기존처럼 `unknown / ok / failed`를 분리하고, `fruit_identity_json`에
전처리 방식과 예측 종류별로 실제 적용한 임계값을 함께 저장합니다.
