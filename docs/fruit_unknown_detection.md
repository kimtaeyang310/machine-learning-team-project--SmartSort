# 과일 종류 분류와 모르는 과일 판별

> 이 문서는 v1 방식의 기록입니다. 현재 학습은 개체 분리·별도 Selection·과일별 기준을 사용하는
> [v2 안내](fruit_unknown_detection_v2.md)를 따릅니다. 아래 개체+날짜 분할과 공통 임계값 설명은 v1에 해당합니다.

사진에서 바나나·귤·토마토를 구분한 다음, 알려진 과일로 받아들인 사진에만 기존 숙도 모델을 적용합니다.
파일명에 과일 이름이 없어도 됩니다. 모르는 과일은 `status=unknown`, `fruit=unknown`, `ripeness=null`로 기록합니다.
사진 읽기·전처리 실패는 `status=failed`이며 모르는 과일 판정과 구분됩니다.

## 실행

프로젝트 폴더에서 기존 `.venv-yolo` 환경을 사용합니다.

```powershell
# 새 과일 종류 모델 학습 + 기준 비교 + 독립 Test 평가
& ./.venv-yolo/Scripts/python.exe -m src.train_fruit_classifier

# 저장된 모델·임계값 그대로 재평가 (Test에서 재조정하지 않음)
& ./.venv-yolo/Scripts/python.exe -m src.evaluate_fruit_classifier

# 이미지 기반 종류 판별 → 모름 판정 → 숙도 예측
& ./.venv-yolo/Scripts/python.exe -m src.predict data/predict_list

# 모르는 과일 폴더로 동작 확인
& ./.venv-yolo/Scripts/python.exe -m src.predict data/grape
& ./.venv-yolo/Scripts/python.exe -m src.predict data/lemon
```

`main.py`에서는 4번이 새 종류 분류기 학습·기준 선택, 5번이 저장 기준 평가입니다.
3번은 이미지 기반 종류 판별이 포함된 폴더 예측입니다. 1·2번은 기존 숙도 학습·평가입니다.
새 분류기가 없으면 학습 안내와 함께 중단하며, 파일명 판별로 자동 전환하지 않습니다.

기존 파일명 방식이 필요한 비교 실험에만 `--fruit-mode filename`을 사용합니다.
이 모드는 모르는 과일을 거부하지 않으므로 일반 예측에는 사용하지 마세요.
단일 이미지 API `predict(...)`도 기본은 이미지 기반이며 모르는 과일이면 `unknown`을 반환합니다.
기존 명시적 과일 인자를 쓰려면 `predict(..., fruit="tomato", fruit_mode="filename")`으로 호출합니다.

## 모델과 교재 방식의 적용

- ImageNet 사전학습 MobileNetV3-small의 가중치는 고정하고, 평균 풀링한 576차원 특징 위에
  3종 다항 로지스틱 회귀 분류 헤드를 학습합니다. 헤드의 확률은 softmax입니다.
  현재는 전체 신경망을 미세조정하지 않습니다.
- 교재와 같은 두 점수를 비교합니다. MSP 점수는 `1 - 최대 종류 확률`입니다.
- 임베딩은 분류 헤드 직전의 특징을 L2 정규화합니다. 학습 기준 벡터 중 가장 가까운
  5개의 코사인 거리 평균을 사용합니다. 숙도 모델의 확률·특징은 이 판별에 사용하지 않습니다.
- 두 점수 모두 높을수록 낯선 사진입니다. 알려진 과일 Calibration 점수의 95백분위수
  (`higher`)를 임계값으로 계산하고, `점수 > 임계값`일 때 모르는 과일로 거부합니다.
  동률은 통과하므로 표본 수·동점에 따라 경험적 통과율이 95%보다 조금 높을 수 있습니다.
- 같은 약 95% 통과 조건에서 포도·레몬 Selection의 오수락률이 낮은 방법을 선택합니다.
  동률이면 알려진 과일 Calibration 오거부율이 낮은 방법, 다시 동률이면 임베딩 거리를 선택합니다.
- 모델 선택 후 알려진 과일 Train+Calibration 전체로 다시 학습하지 않습니다.
  기준 벡터·분류기·임계값의 관계를 그대로 유지합니다.

## 데이터 분리

기존 알려진 과일 Test는 최종 평가에만 사용합니다. 기존 Train에서 5-fold 그룹 분할의
첫 fold를 Calibration으로 빼고 나머지를 새 분류기의 Train으로 사용합니다.
분할 시 과일·숙도 조합을 고려하고 기존 원본 그룹/개체+날짜 그룹을 보존합니다.
전체 Calibration에서 약 95% 통과를 맞추며 과일마다 각각 95% 통과를 보장하지 않습니다.

`data/grape`와 `data/lemon`은 각 과일 안에서 Selection/Test를 약 절반씩 분리합니다.
정확히 같은 픽셀이나 dHash 해밍 거리 4 이하의 유사 사진은 같은 그룹으로 묶습니다.
어떤 사진이 어디에 쓰였는지는 manifest에 경로·그룹·내용 해시로 저장합니다.
서로 다른 분할에 같은 내용 해시나 기존 그룹이 있으면 학습을 중단합니다.

현재 알려진 과일 그룹은 기존 정책을 따르므로 같은 개체의 다른 날짜 사진이 서로 다른
분할에 들어갈 수 있습니다. 포도·레몬도 개체·연속 촬영 메타데이터가 없어 유사도 검사만으로
독립성을 완전히 보장하지는 않습니다. 새 개체·다른 촬영 환경에 대한 검증은 별도로 필요합니다.
Test를 보고 반복해서 설정을 바꾸었다면 새로운 미사용 자료로 최종 성능을 확인해야 합니다.

## 결과와 오류율

학습 결과는 `models/fruit_classifier.joblib`에 저장합니다. 기존 `ripeness_by_fruit.joblib`은 변경하지 않습니다.
새 파일에는 종류 분류 헤드, 특징 추출기 가중치, 기준 임베딩, 임계값, 선택 방법, 분할 목록이 들어 있습니다.
처음 학습할 때 공식 PyTorch 가중치를 프로젝트 내부 캐시에 내려받고, 저장된 모델의 예측은 인터넷 없이 가능합니다.
특징 캐시는 `data/features/cache/fruit_identity`이며 이미지 내용과 특징 추출기 상태에 따라 분리됩니다.

`outputs/fruit_classifier/실행폴더/`:

- `report.md`: MSP·임베딩의 비교표와 과일별 최종 오류율
- `report.json`: 임계값, AUROC, 종류 정확도, 수락하면서 종류도 맞힌 비율, 오류 건수·분모
- `predictions.csv`: 사진별 정답 종류, 분할, 후보 종류, 두 점수, 임계값, 수락 여부, 종류 확률
- `split_manifest.json`: 학습 실행의 경로·그룹·내용 해시·분할 기록

두 오류율은 다음처럼 계산합니다.

| 지표 | 분자 | 분모 |
|---|---|---|
| 알려진 과일 오거부율 | 바나나·귤·토마토를 모른다고 거부한 사진 수 | 알려진 과일 전체 사진 수 |
| 모르는 과일 오수락률 | 포도·레몬을 알려진 과일로 받아들인 사진 수 | 포도·레몬 전체 사진 수 |

알려진 과일끼리의 종류 오분류는 위 두 지표와 다르므로 종류 정확도로 따로 보고합니다.
검증에서 95% 통과를 맞춰도 새로운 Test에서 같은 통과율이 보장되지는 않습니다.
모르는 과일 결과는 포도·레몬 표본에 대한 결과이며, 모든 과일이나 비과일에 대한 보장이 아닙니다.
`unknown`은 엄밀하게는 지원 과일로 받아들일 근거가 부족하다는 뜻이어서, 낯선 조명·구도의 바나나도 거부할 수 있습니다.

폴더 예측은 기본적으로 `outputs/predictions/실행시각.csv`와 `.manifest.json`을 저장합니다.
`--results-csv 경로`로 변경할 수 있습니다. 종류 판별 점수·임계값·확률·모델 해시는
`fruit_identity_json`, 종류 판별 시간은 `fruit_identity_ms`에 들어갑니다.
정상 숙도 판정·모르는 과일·처리 실패 장수를 따로 집계하며, FPS는 정상 처리와 모름 판정을 포함합니다.
종류 판별이 추가되어 기존 숙도 예측만의 속도와 직접 비교할 수 없습니다.
